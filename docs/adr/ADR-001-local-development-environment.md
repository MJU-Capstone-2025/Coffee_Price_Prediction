# ADR 001: Apple Silicon 로컬 개발 환경

## 상태 (Status)

수락됨

결정일: 2026-09-12.

## 배경 (Context)

기존 연구 notebook은 Colab의 Drive mount, `/content` 경로, 셀 내부 패키지 설치에 의존한다. 새 수집·검증 코드를 로컬에서 개발하려면 실행 환경과 경로 기준을 정하고, 기존 연구 결과와 환경 이전 작업을 구분해야 한다. 프로젝트에는 Apple Silicon Mac의 CPython 3.14 가상환경이 이미 마련되어 있다.

## 결정 (Decision)

새 구현은 Apple Silicon Mac, 프로젝트별 `.venv`, CPython 3.14 native arm64를 기준으로 개발한다. 기존 `.venv`를 유지하고 저장소 기준 경로를 사용한다.

새 코드에는 Colab 전용 모듈, Drive mount, `/content` 경로, notebook 내부 패키지 설치, CUDA 필수 전제를 도입하지 않는다. 의존성은 실제 설치·검증한 버전만 requirements 또는 lock 파일에 기록한다. 기존 Colab 패키지 목록 전체를 복사하지 않는다.

레거시 notebook과 저장 결과는 조사·비교 자료로 보존한다. 환경 이전과 모델·전처리 변경은 별도 작업으로 구분한다.

## 결과 (Consequences)

### 긍정적

#### 실행 환경과 경로 기준이 명확해진다

수집 코드와 notebook을 같은 Python 환경에서 실행하고, 개인 Drive 경로 의존성을 줄일 수 있다.

#### 기존 연구 결과를 비교 기준으로 보존할 수 있다

환경 이전에 따른 변경과 모델·전처리 변경의 영향을 구분하기 쉬워진다.

### 부정적

#### Python 버전과 플랫폼에 맞는 의존성 검증이 필요하다

CPython 3.14와 Apple Silicon에 맞는 wheel 및 기능 동작을 확인해야 한다. 호환되지 않는 패키지가 있으면 개발 일정이나 의존성 선택에 영향을 준다.

#### Colab 전용 코드를 그대로 재사용하기 어렵다

경로·인증·패키지 설치 방식을 로컬 실행에 맞게 분리해야 한다. 기존 CUDA 기반 학습의 실행 가능성은 별도로 검토해야 한다.

### 중립적

#### 환경 선택과 기능 검증은 별개다

이 결정은 개발 기준을 정한다. Core-4 API 수집, GPU·MPS 학습, 새 환경 재설치의 성공을 보장하지 않는다.

#### 실제 호환성 문제를 근거로 환경을 재검토한다

필수 패키지의 wheel 확보나 기능 동작에 문제가 확인되면 영향과 대안을 비교해 Python 버전 또는 패키지 변경을 검토한다. 네트워크 접근 실패를 패키지 비호환으로 판단하거나, 임의 소스 빌드·버전 하향·패키지 교체로 문제를 숨기지 않는다.

## 검토한 대안 (Options)

### 대안 1: Colab 환경 재사용

기존 notebook의 실행 방식과 가깝지만, 새 구현에도 Drive 경로와 세션별 환경 의존성이 남는다. 로컬 개발 기준을 세우려는 목적에 맞지 않아 채택하지 않았다.

### 대안 2: Python 버전 하향 또는 패키지 교체

호환성 문제의 해결책이 될 수 있으나, 현재 마련된 환경을 먼저 검증하기로 했다. 구체적인 호환성 문제가 확인될 때 재검토한다.
